# Kimi Quota Bar：视觉升级与轻量功能开发计划

编写日期：2026-10-30（Asia/Shanghai）
代码基线：`c155c2c`，项目版本 `0.1.4`
状态：`0.2.0` 已在 `kimi-bar-new` 分支实施；已完成离线检查、浏览器沙盒与 macOS 原生运行验证。Windows 实机视觉与双端性能验收仍需在对应环境补测，不以构建成功代替视觉验收。

## 1. 要做成什么样

把它做成一件精致的小型桌面仪表：收起来是一颗清晰、有质感的额度浮珠，展开是窄而舒服的三行卡片。色彩可以丰富，数字始终稳定，平时安静，操作时有恰到好处的反馈。

主方案已经明确，可以直接按本文开工：

- 主卡片由 **328×224 改为 280×252 逻辑像素**：宽度减少48像素，约14.6%；适当增加高度换取读数和留白，不靠缩小字体变窄。
- 球保留 **60×60 逻辑像素**，中心百分比保持两位小数，取消数字呼吸缩放；进度环、内光、材质重新分层。
- **8套完整主题**贯通浮珠、主卡片、按钮、登录、个人中心、外观页与确认框，包含冷色、暖色、柔彩、浅色和银灰风格。
- 提供按部位编辑的颜色、透明度和光晕，支持预设、实时预览、撤销、保存和主题文本导入导出。
- 动效分为 **静止 / 灵动 / 星尘**。新安装默认灵动，保留旧用户的观赏模式选择；系统减少动态效果优先。
- 本期增加 **7天指标投射到球、点击额度行切换球读数、复制额度摘要、脱敏诊断、离线设计沙盒**。
- 下一期再做工作段记录、采样趋势、提醒和开发工具集成，不让首轮美化变成大型仪表盘项目。

主界面不常驻趋势图、设置表单或开发参数。颜色编辑和诊断都有独立子页，额度仍然是一眼就能读完的小工具。

### 本轮交付边界

本文件是正式实施依据，另附聊天内的布局与配色交互预览。预览使用示例数据与稳定的不透明底色，用于判断配色、比例和布局，不能证明原生玻璃效果、桌面穿透感或实际功耗。预览里的宽度调整用于设计比较；本期产品默认固定280，不新增任意拖拽改宽。

预览含“精致三行”和“主额度聚焦”两个布局：**精致三行是本期实现项**；主额度聚焦仅为下期可选皮肤，不需要二次决策才能开始本期工作。

已审阅 README、包与构建配置、`ui/`界面和登录兜底页、Rust主程序/鉴权模块、现有设计案例及三端发布工作流。以下是源码事实，不是实机性能测试结果。

| 现状 | 对本次开发的意义 | 基线位置 |

### 数据能力边界

当前标准化接口只有月度、5小时、7天的用量比例、窗口启用状态、重置时间和Kimi Code比例（`main.rs:314`）。没有请求明细、精确token数、金额或某次IDE任务用量。

因此本方案中的数字沿用接口口径；不推出“还能问多少次”“还能写多少行代码”“今天花了多少钱”。Code区域写“Kimi Code · 18.60%”并在说明中标为接口返回占比，不重新定义分母。滚动窗口的时间沿用服务端字段，不承诺到时一定恢复满额。

## 3. 主卡片详细设计

### 3.1 尺寸和排版

以下尺寸统一为逻辑像素，最终以原生窗口的逻辑尺寸为准。

| 元素 | 规格 |
|---|---|
| 主卡片 | 280×252，固定宽，圆角18；左右内边距13（含边框后可用内容252） |
| 垂直分配 | 上下边框合计2，内边距各12，标题26，标题下8，三行区156，页脚前8，页脚28；总计252 |
| 标题 | 状态点6 + 间隔6 + “Kimi 额度”，12.5px/600；不放更新时间 |
| 右侧按钮 | 账号、刷新、更多、隐藏，点击区各26×26，间隔4；图标12–14 |
| 额度区 | 每行48高，行间6；三行等高，不采用瀑布式卡片嵌套 |
| 行布局 | `32px minmax(0,1fr) 64px`，列间10；32px进度环 + 标签和时间 + 右对齐百分比 |

### 3.2 材质

采用“薄玻璃 + 有色内衬”：平台材质层按第7节选择，macOS可用原生模糊，Windows默认无原生背板；CSS负责可控的底色、上沿1px低透明高光、轻内阴影和文字。主卡片原则上不加第二层大面积 `backdrop-filter`。

实施时用户明确要求恢复旧版深空极光的紫黑高斯玻璃与焦点态，因此该预设作为材质例外：使用`#161620`与12% CSS覆盖、原生`#1A1A2673` tint，并恢复卡片/浮珠的紫黑渐变和18px模糊。其他预设仍遵循薄玻璃方案。数字后的硬质横向底衬已按用户反馈完全移除，不使用白色胶囊或矩形色块。

- macOS原生材质路径：深色卡片底色初值为主题`background`的88%不透明度；弹层和输入区用`surface`的96%。浅色主题分别94%与98%。Windows默认值由第7节覆盖。这是起始设计值，按实机可读性调校。
- macOS原生材质路径的球底色初值90%，Windows默认94%；中心文字区可通过低强度装饰控制保证读数，不使用明显边界的底衬。
- 外侧发光只做安全边界内的内光。当前窗口和内容同尺寸，外阴影可能被裁切；不为展示漂亮阴影永久扩大透明窗口的点击面积。
- 原生玻璃不支持或表现不稳定时用同主题近不透明底色，保持结构和色彩一致。
- 窗口圆角与原生材质圆角统一：卡片18，球30；不能出现圆球外露方形灰底。

### 3.3 行与菜单交互

- 单击任意已启用的额度行，把该项设为球读数；行尾可访问名称注明“当前球读数”，视觉使用标签旁小点/细小定位标记，避免再加整条彩框。点击不强制收球。
- 未启用行显示“未启用”，不可选；数据未知行保留标签并显示`—`，不当作0%。
- 拖动区改为标题空白、页脚空白；额度行、所有按钮、弹层和表单不触发拖动。标题双击吸边继续保留。
- “更多”只有：外观、浮珠显示、复制额度摘要、诊断、收为浮珠；退出应用仍在托盘。
- `Esc`按层级依次关闭菜单、确认框、子页；主卡片时隐藏窗口。球支持Tab聚焦和Enter/Space展开。
- 图标按钮有名称与焦点环；颜色之外用文字/图标表达高用量、离线和未登录。

## 4. 浮珠设计：漂亮但始终读得清

### 4.1 图层顺序与几何

从后到前为：平台材质层（Windows默认无原生背板）→ 固定主题底色 → 单层低强度氛围光 → 可选星尘 → 轨道/进度弧 → 稳定数字 → 极小状态标记。数字区域有遮罩降低背后装饰亮度，中心约42×20逻辑像素优先保证对比度。

- 默认直径60，保留现有72×72 SVG坐标系、r=30与四周内收4px。
- 进度线宽由6收至5（SVG单位），轨道与进度用同一几何；单层低强度阴影，避免厚荧光管。
- 主数字13px/600，`%`可单独降为10px；100.00%仍保留两位，不因数字变长跳动整个球。
- 0%不显示端点；100%为完整环，端点放12点方向；未知/未启用不画进度。
- 进度端点应使用SVG局部角度`360×ratio`，再随整个SVG旋转-90°；只做一次旋转。
- 悬停提亮内光，不放大整个球，以免被60px窗口裁切。按下缩至0.97，释放回1，80/140ms。
- 球默认显示“已用”；悬停提示明确“月度已用92.72% · 更新于14:32 · 点击展开”。切换到5h/7d后提示与可访问名称立即同步。
- 不在60px内再塞一行常驻小字。本期不加入自动轮播指标，避免看见数字却不知道换了口径。

### 4.2 有意义的微反馈

1. **磁吸收拢**：靠左向左收，靠右向右收，停靠边固定；220ms内完成，前端内容淡变和原生尺寸协调。
2. **数据落定**：仅有效数值改变时进度弧350ms移动；数字直接更新，不滚动翻牌，不每分钟光爆。
3. **主题换色**：同一组图层替换颜色，背景/边线160ms过渡；SVG渐变停止色必要时直接切换，不交叉绘制两套模糊球体。
4. **状态反馈**：离线时增加小静态时钟/状态点，tooltip明确“上次数据”；账号失效则改为`—`与登录提示。高用量不通过高速闪烁表达。

光晕属于主题参数：有效值为当前自定义主题的`overrides.orbGlow`（若有），否则使用基底预设默认；不另保存一份全局光晕值。选择内置预设只更改选中ID，不套用别的主题覆盖值，也不删除已经保存的自定义主题；动效档位保留。透明度同样区分“未覆盖，使用主题/平台默认”与用户明确设置的数值。

老主题ID不变：`abyss`由“深渊紫黑”升级，`rainbow`由“独角兽彩虹”升级。迁移后第一次打开外观页显示旧名提示，后续只显示新名。

### 5.2 状态色与装饰色分开

卡片保留当前用量区间含义：低于50%正常，50%至低于80%注意，80%及以上接近上限。环可以采用状态色；文字数值保持主文字色。浮珠继续用主题渐变，通过文字提示/小状态标记表达异常。

| 语义 | 深色主题默认 | 浅色主题默认 | 必须伴随的表达 |
|---|---|---|---|
| 正常 | `#73D9B0` | `#236B50` | 正常读取时不额外占一行 |
| 注意 | `#EBC17A` | `#825512` | 需要时写“用量偏高” |
| 接近上限/错误 | `#F19B9B` | `#AD3F56` | “接近上限”或具体错误原因，不能同一红点代表所有错误 |
| 未知/过期 | `#A8B2C8` | `#796B80` | `—`、上次更新、未启用等明确文字 |

自定义状态色可以开放，但状态阈值和文案不是颜色配置的一部分。主题底色和透明度变化后重新检查对比度；普通文字以4.5:1为验收目标，关键图形/焦点边界以3:1为目标，玻璃最终合成效果另做深浅壁纸实测。

### 5.3 分部位自定义

从任一预设创建“我的主题”，内置预设只读。界面分组与可调整字段如下：

| 分组 | 可编辑内容 | 初期约束 |
|---|---|---|
| 整体 | 强调色、明/暗基调、卡片与球透明度 | 透明度0.75–1.0；浅主题默认更实；原生材质随基调切换 |
| 浮珠 | 底色、2–5个渐变色、轨道、数字、光晕、粒子2色 | 停点等距；光晕0–0.5；粒子数量不向用户无限开放 |
| 卡片 | 背景、surface、边线、主文字、副文字、额度环轨道 | 登录、个人中心、菜单、确认框自动继承 |
| 控件 | 按钮强调色、按钮字色、选中底色、焦点色 | 未单独设置的字段从主题派生 |
| 状态 | 正常、注意、接近上限、未知色 | 搭配固定文案，不能覆盖数据判断逻辑 |

每个色项为色块 + HEX输入；只接受`#RRGGBB`，透明度独立滑杆。支持还原当前字段、还原本分组、还原到基底预设；不需要用一个全局重置抹掉所有配置。

本期可保留最多8个命名自定义主题，主题页底部以同样的缩略色块显示。每项存稳定ID、名称、基底预设ID与覆盖值；选另一预设不删除已保存主题。首次另存默认为“我的主题”，编辑已有项默认保存到原项，另存为明确入口。超过8项时提示先整理已有项；不静默覆盖。托盘保留8个预设及“自定义 · 当前名称”一项，完整自定义列表放外观页。

编辑使用草稿，操作即时更新外观页内的浮珠/卡片样品，样品使用不透明底色预览；主窗口材质与其他页面在保存后才改变。“保存”提交，“取消/返回”放弃草稿。隐藏窗口或从托盘切换预设时结束草稿，再应用正式选择；不把未保存值悄悄写盘。草稿内记录最近20步，撤销/重做只影响本次编辑。本期不做原生材质草稿预览，从而避免延迟预览在取消后回写窗口。

主题分享用“复制主题文本”和“粘贴主题文本”输入框；用户主动粘贴，不自动读取剪贴板。导出仅含主题名、基底ID与颜色参数，不含账户或窗口位置。文件导入导出留下一期，避免为小需求增加文件选择链路。

## 6. 动效与功耗设计

### 6.1 三档效果，清楚限定每一层

| 档位 | 常驻装饰 | 交互反馈 | 默认与使用条件 |
|---|---|---|---|
| 静止 | 无循环动画、无Canvas；保留静态材质与渐变 | 按钮80–140ms，进度可直接更新；系统减少动态效果时取消几何过渡 | 专注、省电、辅助功能 |
| 灵动 | 只有一个氛围层24秒慢转；不再叠呼吸、CSS粒子和游星 | 进度350ms、换色160ms、收展200/220ms | 新安装默认；超过15秒无悬停/操作后冻结在当前相位，悬停唤醒 |
| 星尘 | 单Canvas保留旧观赏模式的16枚微粒+内外双游星；不叠旧CSS粒子；30fps绘制上限 | 同灵动；端点亮点常静并跟随数值 | 主动选择；只在球可见时运行 |

实施时用户明确选择：星尘档保留旧观赏模式的华丽度、粒子密度、双游星与辉光；只有灵动档按精简方案落地。灵动的“静置冻结”不影响额度刷新。星尘模式延续现有精灵缓存、DPR≤2；不随每帧生成渐变、重建精灵或读取DOM尺寸。环内数字静止，所有档位都不做整球悬停放大。

优先让装饰动画只改变`transform`/`opacity`，避免反复改模糊半径、阴影、尺寸和背景渐变本身。`will-change`仅加到确实需要的少数层；性能是否提升以追踪结果为准。[web.dev动画性能指南](https://web.dev/articles/animations-guide)

### 6.2 单一动效开关与生命周期

装饰引擎运行条件为：原生主窗口可见 AND 文档可见 AND 当前是球 AND 星尘档 AND 系统未要求减少动态效果。灵动也受同一可见性条件控制，加15秒活跃窗口条件。

- Rust在显示/隐藏/形态切换时发送状态，前端同时监听`visibilitychange`，不把“失去焦点”当作不可见。
- 隐藏、展开为卡片、减少动态效果开启时停止Canvas、清除调度、暂停CSS，不保留隐藏的空转循环。
- `startOrbFx()`自身再次检查门禁，防止隐藏中切主题又启动动画。
- 监听`matchMedia`的change，运行中修改系统偏好立即生效；高对比度模式关闭所有装饰层，含Canvas、tip和外圈星。
- 在跨DPI变化和尺寸真正改变时重建画布；切主题时更新缓存；普通帧不重分配。
- 现有实现只是30fps“绘制”节流，rAF回调可能仍随屏幕刷新率运行。开发时分别统计回调与绘制次数；若唤醒仍高，用一个可取消定时器配合一次rAF控制绘制节拍，不能宣称30fps就等于CPU减半。

浏览器通常会节流后台rAF，但这不代替Tauri原生窗口状态通知；是否触发可见性事件必须在WKWebView/WebView2验证。[MDN Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)

### 6.3 原生窗口动画

保留短时原生尺寸动画，首轮定为收拢200ms、展开220ms，曲线使用无越界的`easeOutCubic`；轻微弹性只放在内容层。低动效直接到目标位置/尺寸。

新增generation取消标记：新展开/收拢/子页请求使旧动画失效；最终精确设置目标尺寸一次。每个Moved不再新建睡眠线程，改成一个可重置防抖任务。程序化移动不触发二次吸边，也不写入中间位置。任何打开子页的请求只有一个最终目标，不先展开到252再被旧动画改回去。

### 6.4 性能验收预算

下列是待测目标，不是本轮已测结论。使用release构建，同设备、同壁纸、同刷新节奏、同电源状态、同显示器刷新率，与`c155c2c`基线比较，统计应用及所属WebView/GPU进程。

| 场景 | 验收目标 |
|---|---|
| 隐藏10分钟 | 装饰rAF、Canvas绘制、CSS装饰动画均停止；额度轮询策略明确；无线程持续增加 |
| 静止球/静止卡片 | 无装饰定时循环；CPU相对基线静态场景不增加超过0.3个百分点（按单逻辑核100%口径） |
| 默认灵动球 | 15秒后无持续装饰绘制；静置CPU不高于旧默认球；活动时无持续全窗口重绘 |
| 星尘球 | Canvas≤30次绘制/秒；目标绘制回调p95<2ms；若实机不达标先降密度/光晕 |
| 内存 | 预热后相对同场景基线目标增加≤10MiB；100次开合、50次换主题后无单调增长 |
| 操作 | 按下反馈目标<100ms；窗口收展目标≤250ms；无明显闪白、端点跳位或旧动画回写 |
| 资源 | 前端新增运行资产目标≤100KiB未压缩（不含开发fixtures/文档）；无在线字体和装饰图片请求 |

CPU采集排除启动和正常网络请求短峰；每场景预热30秒、观察至少3分钟、重复3次记录中位数与峰值。电池功耗不以一台机器的CPU百分比替代；macOS记录Energy Impact/唤醒，Windows记录相关进程CPU/GPU与内存。平台无法测到的项在交付中明确列为未测，不能用浏览器预览替代原生验收。

## 7. 双端材质专项：Windows蒙版背景必须解决

**用户补充的明确要求：不仅完成Mac效果，Windows也要好看；以前Windows出现过蒙版背景难看。本节为本期硬性范围，不是下期优化。**

当前源码在macOS切换球/卡片时重设原生材质圆角；Windows只在启动时应用一次固定深色Acrylic，没有对应的球态材质切换。这是需要排查的实现差异，不能仅凭源码认定它就是历史问题的唯一原因。本轮没有复现用户当时的Windows界面。

另已核对本项目锁定的`window-vibrancy 0.6.0`依赖源码：Windows build≥22523走系统backdrop分支，`apply_acrylic`传入的RGBA未参与该分支；因此只把深色参数改成浅色，不能保证白瓷主题正确。该版本已有`clear_acrylic`，可在统一材质入口使用。依赖官方说明也列出了部分Windows版本的拖动/缩放性能问题，原生窗口动画需实际验证。[window-vibrancy官方说明](https://github.com/tauri-apps/window-vibrancy)

### 7.1 视觉必须相同，底层材质允许因平台而异

两端必须统一280×252卡片、60球、18/30圆角、主题颜色、字级、按钮、间距、状态、动效档位。不要以系统材质差异为由接受Windows上明显的灰色方底、黑色蒙版、白色角落或颜色浑浊。

材质实现使用统一的`apply_material(form, appearance, materialMode)`入口，显示、形态切换、换主题、系统外观变化都经过它。旧效果必须先清理，再应用新效果，不能层层叠加。

| 场景 | macOS方案 | Windows方案 | 统一验收标准 |
|---|---|---|---|
| 默认主卡片 | 现有Liquid Glass，失败回退vibrancy；CSS控制色调 | 默认使用精修的CSS雾面底，禁用整窗Acrylic；原生增强玻璃完成验证后作为可选项 | 明暗壁纸均清楚，不泛脏灰，不闪白 |
| 默认球 | 原生圆形材质经30圆角处理，CSS不再重复blur；若有方底则降级 | 默认清除Acrylic/其他整窗材质，用透明原生窗+CSS圆形底色/内光 | 四角完全透明，桌面上没有60×60灰方块或圆角方形托底 |
| 浅色白瓷 | 同步native light外观/tint，不能仍强制Dark | 用浅色雾面底与深字；不在白底上残留固定深色Acrylic | 底色干净，阴影不发黑，按钮文字可读 |
| 不支持/不稳定系统 | 同主题实体底色，保留CSS质感 | 同主题实体底色，保留CSS质感 | 功能、布局和配色完整；不退回无设计的纯黑面板 |
| 用户关闭系统透明效果 | 尊重系统偏好或提供“实色”选择 | 实色雾面作为可靠路径 | 不因失去模糊而失去文字对比度 |

Windows默认“雾面”不是丢掉设计：仍保留精确底色、细高光、层次、主题渐变和柔和内光，只避免让整窗Acrylic决定最终背景。默认卡片不透明度先用96%，球94%；必要时升到100%，而不是降低到能看见底层灰板。两端实际合成的色差要在同壁纸上比较。

**不能把CSS `backdrop-filter`当作必然能模糊WebView外部桌面的替代品。** 浏览器预览中的背景模糊与原生桌面玻璃不是同一条渲染路径。Windows是否启用增强玻璃，以真实透明窗口的效果和性能为依据。

### 7.2 Windows专用实施点

1. 从启动时无条件`apply_acrylic`改为统一材质策略；球态在改变尺寸前清除整窗效果，卡片态按模式恢复。检查依赖实际提供的clear接口，不自行叠多种Windows合成API。
2. 核实透明WebView背景、窗口背景、`html/body`、卡片/球背景五层；每层指定职责，禁止全窗口透明黑层长期覆盖球的四角。
3. 球用固定60×60的外层裁切，装饰层都在圆内；CSS圆角不能被当作原生材质一定圆形的证明。先保证默认无原生底板路径正确。
4. 检查1×、1.25×、1.5×、2×缩放下窗口尺寸舍入、圆边抗锯齿与1px漏色；球中心和进度环必须同心。
5. 在窗口失焦、显示/隐藏、连续收展、跨屏及唤醒时复查材质。不能只测初始截图。
6. 浅色主题同步去除深色tint；主题切换只执行必要的材质更新，不每帧重新申请系统效果。
7. 使用系统字体栈覆盖Windows字体；`100.00%`、中文标签、长会员名都用实际Segoe UI/Microsoft YaHei渲染检查，不能只靠Mac字体测宽。
8. 如增强玻璃产生灰方底、拖动卡顿或失焦变色失控，自动/手动回到雾面；诊断页标记最终材质及回退原因。增强效果不通过时不作为默认发布。

WebView2宿主背景显式设为全透明，半透明放在CSS层；其默认背景接口支持透明/不透明，不支持任意中间alpha。首次白闪先核对背景设置时机，再检查是否需要在WebView创建前配置背景。[微软WebView2背景说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2controller2?view=webview2-1.0.3537.50)

不要用Windows 11的DWM圆角提示保证18px卡片或30px正圆：它不能精确指定这些半径，透明/自定义region窗口也有适用限制。先交付无背板的CSS透明方案；只有仍有合成残影或四角挡点击时再验证最小原生裁剪适配，并检查DPI、抗锯齿与资源释放。[微软桌面窗口圆角说明](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-rounded-corners)

若Windows连续改原生尺寸仍残影或卡顿，使用已定义的后备：一次提交目标窗口几何，内容层140–180ms淡入/微缩放完成反馈，停靠锚点不变。两端共享后备实现，不强求有问题的平台播放同一条原生缩放动画。

- **没有Windows实机或虚拟机GUI验收证据，不宣称双端视觉适配完成。** 可以先交付开发结果和Mac验证，但Windows专项保持未完成状态。

| 首次加载 | 三行占位`—`，页脚“正在获取额度” | 静态`—` | 无循环骨架屏 |
| 新鲜成功 | 三项比例与时间 | 当前项比例 | 有变化才做弧线过渡 |
| 刷新中且有旧数据 | 保留数字，刷新按钮转动 | 保留数字 | 不清空重画；禁止重复请求 |
| 暂时断网/服务错误，有本账号旧快照 | 保留数据并标“上次更新14:32 · 暂未刷新” | 旧比例+静态过期标记，tooltip说明 | 不显示正常成功状态 |
| 超过5分钟没有成功数据 | 仍可在卡片查看上次数据并显示时间 | 主读数改`—`，避免远处误认实时数据 | 回来后立即刷新 |
| 未登录/登录失效/主动退出 | 未登录入口 | `—`，点击进入卡片 | 清除旧账号快照，旧响应不可回填 |
| 指标未启用 | 该行`—/未启用` | 若选该项则`—` | 其他正常指标照常显示 |
| 某字段缺失或非法 | 仅该字段`—` | 选中该字段则`—` | 不把NaN、Infinity、空字符串当额度 |

当前`normalize()`对proto3“存在统计对象但省略零值字段”的兼容要保留；不存在统计对象不等同0%。进度几何可clamp到0–1；对显式越界值标记异常，不能静默把异常数据伪装成正常满额。

解析必须在Rust端分三支：统计对象缺失→unknown；对象存在且比例字段缺席→0；字段存在但为null、空串、非有限数或错误类型→invalid。当前`ratio_of(...).or(zero_if(stat))`会把部分非法字段误补0，必须同步修改，不能只在前端检查`isFinite`。

前后端增加会话代次。主动退出、登录完成、跟随桌面账号变化时重置本账号内存快照；请求开始时记录代次，返回时不匹配就丢弃。账号变化可由Rust的本机身份比较生成不含原始ID的状态标记，不把JWT/token给前端。

正式所有权放在Rust：`sessionGeneration + inFlight + lastSuccessSnapshot`由后端维护，前端是显示镜像与请求调度器。请求合并按代次分组，新账号刷新不能加入旧账号在途请求；旧请求的完成回调也不能清除新请求的loading状态。复制摘要读取同一后端快照并检查账号/过期；状态变更广播给前端。分钟tick同时重算5分钟过期，即使正在退避也应准时把球改为`—`。

### 8.3 请求与刷新反馈

- 保持可见时60秒刷新，单一调度器；上一请求未完成时，手动/自动/托盘刷新复用当前请求，不发第二个。
- 刷新按钮跟随真实请求结束，成功短暂显示完成，失败显示状态；不再固定转1.2秒。
- 本期没有后台通知：主窗口完全隐藏时暂停额度轮询；再次显示时若快照已满60秒或上次失败，立即刷新。球可见算可见。
- 临时失败最多按60/120/240/300秒退避；手动刷新可主动重试但仍合并正在进行的请求；成功恢复60秒。
- 登录二维码轮询有自己的生命周期：只在二维码页实际打开时运行，切到短信/关闭/收球时停止；返回扫码页按ticket状态恢复或重新生成。
- 重置倒计时按分钟更新，不开每秒总表计时器；在唤醒、重新显示时按真实时钟重新计算。
- 到达重置时间显示“等待更新”，等待服务端结果，不本地强行清零。

### 8.4 复制额度摘要

更多菜单一键复制，输出例：

### 8.5 诊断与离线设计沙盒

**普通用户的诊断页**：应用版本、系统与WebView版本（能可靠获取时）、最后成功时间/请求耗时、当前材质/回退原因、逻辑尺寸/DPI、当前主题和动效档位、最近脱敏错误。默认不显示实时帧率，只有进入诊断页才采样必要字段。复制的是白名单结构，不是原始日志全文。

**开发沙盒**：新增开发专用入口，复用正式渲染函数，注入fixture，不读取登录态、不请求Kimi、不写真实设置、不更新真实窗口位置。明确显示“演示数据”；fixtures与调试控件不进入正式前端分发目录。

必备场景：0、49.99、50、79.99、80、99.99、100%；0/25/50/75/100%端点；无数据、禁用、登录失效、断网后旧数据、长时间未刷新、长中文/英文会员名、超长错误、浅/深主题、快速连续换主题、显示比例变化。

开发叠层按需显示rAF回调数、Canvas实际绘制数、粒子数和材质模式；关闭面板就停止采样。新增离线`--check-layout`/`--check-settings`可用于原生窗口验证；不能让UI测试顺手拉真实额度。

### 9.2 设置：一个正式来源，旧值可迁移

正式来源选择应用配置目录下的`settings.json`，与加密会话分离。Rust持有已校验设置，前端只持有镜像与编辑草稿；托盘、主界面、原生材质都从这份状态派生。localStorage仅在旧版迁移时读取，不再作为第二份正式配置。

设置示意（键名在实现时固定）：

```json
{
  "schemaVersion": 1,
  "theme": {
    "selectedId": "abyss",
    "customThemes": []
  },
  "orb": { "metric": "total", "decimals": 2 },
  "motion": { "preset": "lively" },
  "material": { "mode": "auto" },
  "layout": { "density": "compact" }
}
```

自定义项结构为`{ id, name, basePresetId, overrides }`；selectedId可指向内置ID或自定义ID。加载时检查引用存在；自定义项先解析基底预设，再应用白名单覆盖，再应用必要的平台可读性回退。回退不覆盖用户原值，诊断显示实际生效值。首次迁移只填selectedId与既有指标/动效，不构造多余的“自定义”。

`material.mode`为`auto/matte/enhanced`：auto按本节双端默认策略；matte强制可靠雾面；enhanced只在验证过的平台生效，失败回退并显示原因。不是用户修改JSON就能绕过平台能力检查。

迁移规则：首次检测不到settings文件时，`get_ui_config`只返回内存默认与`needsMigration=true`，不得提前落盘。前端读取旧`kqb-orb-theme`、`kqb-orb-metric`、`kqb-orb-showcase`后调用迁移；Rust在锁内重查文件仍不存在后提交，成功才开放普通保存/托盘变更。旧theme/metric合法则保留；showcase为1映射星尘，为0映射灵动。再次启动只读正式文件。旧键暂留一个版本，避免迁移失败丢偏好。

恢复顺序为正式文件→上一份有效备份→内存默认并报告错误。坏值不阻止启动；高于程序支持的schemaVersion不能被默认值自动覆盖，使用兼容默认运行并禁用覆盖保存，提示升级应用。迁移读取失败则保留旧键，进入可重试状态；不能把没有读到旧设置当成用户主动恢复默认。

保存用临时文件写入后替换，保留上一份有效设置；Windows的替换行为要验证，不能只在Mac上证明原子保存。写盘仅在保存/托盘选择等提交时发生，颜色拖动只更新内存草稿。写失败显示“未保存”，继续使用原有效设置。

主题导入限制为16KiB以内、JSON对象、schemaVersion、白名单字段、合法HEX/范围；主题名最多24个字符。拒绝CSS字符串、URL、脚本和超量渐变stop。未知高版本导入明确提示不支持，不静默丢色。自定义值经JSON序列化传递，不能拼接进eval字符串。

### 9.3 需要的接口契约

| 命令/事件 | 输入/输出与作用 |
|---|---|
| `get_ui_config` | 返回布局规格、8套预设、已保存settings、revision、是否需迁移；不含账号信息 |
| `migrate_settings` | 只接收3个旧设置白名单；仅在正式配置不存在时执行 |
| `save_settings` | 接收完整草稿+expectedRevision；验证后提交，返回实际生效值/revision；冲突不静默覆盖 |
| `settings-changed` | Rust广播已保存设置；前端重绘、托盘单选、材质更新保持一致 |
| `set_panel_layout` | 输入quota/login/profile/appearance/diagnostics之一；Rust决定宽高并夹到工作区 |
| `app-visibility` / `form-changed` | 包含visible、form、generation；前端幂等应用，不重复启动Canvas |
| `get_quota` | 保留现有字段，补错误类别、快照时间、会话代次；合并并发请求、丢弃旧代次结果 |
| `copy_quota_summary` / `copy_diagnostics` | Rust从已允许的结构生成文本并复制，返回成功/错误，不接受任意原始日志 |
| `get_diagnostics` | 返回白名单字段；省略无法可靠获取的指标并说明，不编造系统版本 |

前端草稿只改变外观页的样品颜色，不发送原生材质变更、不新增草稿IPC。保存成功后统一重放实际材质与全局主题；托盘勾选只反映保存值。若expectedRevision冲突，提示“设置已在其他入口变化”，保留可复制的草稿并让用户重新载入，禁止自动覆盖新值。

保留球态“事件+eval”兼容通路，但两路共用一个带generation的幂等处理器；同一事件不会播放两次入场动画。常规新设置优先用结构化事件/命令。启动先完成配置与主题应用再显示窗口；超时则显示可读默认界面，不能无限白屏。

### 9.4 尺寸、DPI与位置持久化

- 布局规格由Rust结构统一提供，前端消费；Tauri初始配置作为启动镜像，由离线一致性检查防漂移。
- 内部窗口计算使用物理像素，设计值全部以目标显示器scaleFactor换算；工作区原点和尺寸也统一单位。Tauri窗口创建尺寸是逻辑像素，而显示器位置/尺寸有物理坐标语义，应显式转换。[Tauri Window参考](https://v2.tauri.app/reference/javascript/api/namespacewindow/)
- 使用工作区而非整屏，预留菜单栏/Dock/任务栏；先检查当前锁定Tauri版本支持的工作区API，不为了一个API盲升版本，必要时做最小平台适配。
- 进入/退出吸附阈值改为28/48逻辑像素后再转换，保留滞回；跨DPI拖动手感一致。
- 所有目标位置限制x和y；窗口比工作区还大时先限制尺寸，再clamp，避免min>max。
- 卡片位置、球停靠边/纵向比例分别保存；隐藏球不覆盖上次卡片位置；移除外接屏后恢复到可见工作区。
- 快速开合、打开子页、屏幕缩放变化都取消旧几何动画；动画结束只保存最终状态。

## 13. 开工用的最终约定

1. 默认落地280×252精致三行、60球、两位小数、已用口径、深空极光、灵动15秒后静置。
